Git & GitHub,
from zero to confident.

Git is the version-control system. GitHub is the place that hosts it and adds a social/collaboration layer on top. This page covers everything: terminology, the commands you actually use daily, GitHub features (PRs, Issues, Actions, Pages), the GitHub Marketplace, and how AI tools (Claude Code, Copilot, Cursor) plug in.

30-second mental model. Git tracks every change to your files. GitHub stores that history online so you (and others) can collaborate. A "repo" is a project. A "branch" is a parallel version of the project. A "pull request (PR)" is asking to merge a branch into the main version. That's 80% of it.
Why this matters

Even non-coders need GitHub now

  • AI tools store everything on GitHub. Skills, MCP servers, n8n templates, prompt libraries — all on GitHub.
  • Claude Code and Cursor live on GitHub. You'll clone repos, create branches, open PRs daily.
  • It's your portfolio. Recruiters look at GitHub before LinkedIn now.
  • It's the only honest "save". Cloud docs hide history. Git shows every change, who, when, why.
  • Free hosting. GitHub Pages = free static website hosting. NEXUS itself can be hosted there in 2 clicks.
Setup

Install Git, create a GitHub account

  1. Sign up at github.com — free. Use your real name + a professional username.
  2. Install Git:
    • Windows: download Git for Windows — comes with Git Bash terminal, very useful.
    • Mac: brew install git (or it comes with Xcode Command Line Tools).
  3. Configure your identity — only do this once per machine: 
    git config --global user.name "Your Name"
git config --global user.email "your@email.com"
git config --global init.defaultBranch main
  4. Authenticate to GitHub — easiest way is the official GitHub CLI: 
    # Install gh
# Mac:    brew install gh
# Windows: winget install --id GitHub.cli

# Then log in (one-time)
gh auth login
# Pick GitHub.com → HTTPS → Yes auth Git → Login with browser → done
Core commands

Daily git, in plain English

CommandWhat it actually does
git clone <url>Download a repo to your computer.
git statusWhat's changed since last commit. Use this constantly.
git add .Stage all changes for the next commit.
git add <file>Stage just one file (safer than git add .).
git commit -m "message"Save a snapshot of staged changes with a description.
git pushUpload your local commits to GitHub.
git pullDownload the latest changes from GitHub into your local copy.
git checkout -b feature-nameCreate a new branch and switch to it.
git checkout mainSwitch back to the main branch.
git log --onelineSee your commit history (one line each).
git diffShow what's changed but not yet committed.
gh repo createCreate a new GitHub repo from the current folder.
gh pr createOpen a PR for the current branch — saves clicking around the website.

The 90% workflow you'll use every day

# Start a new feature
git checkout main
git pull
git checkout -b add-search-feature

# Make your changes…
# Then save them
git add .
git commit -m "feat: add search bar to home page"
git push -u origin add-search-feature

# Open a PR (GitHub website OR command line)
gh pr create --title "Add search feature" --body "Adds a search bar to the home page"

# After it's merged
git checkout main
git pull
git branch -d add-search-feature  # clean up
Beyond git

GitHub features worth knowing

🔃
Pull Requests (PRs)

A formal request to merge your branch into main. Where code review happens. Comments, suggestions, approval, then merge. Even solo, use PRs — they document why you made each change.

🐛
Issues

Bug reports, feature requests, todos. Linked to PRs ("Closes #42"). Use them as your project's todo list.

⚡
Actions

Automation that runs on events (push, PR, schedule). Run tests, deploy, lint, build, post to Slack. Free for public repos, generous free tier for private. The most powerful free feature on GitHub.

🌐
Pages

Free static hosting. Push HTML/CSS/JS to a repo → it's live at username.github.io/repo. NEXUS could be hosted here for £0.

📦
Releases

Tagged versions of your project (v1.0.0, v1.1.0). Auto-generates downloadable zips. Use Actions to publish releases automatically.

🔐
Secrets

Store API keys / tokens encrypted at the repo or organisation level. Available to Actions but never exposed in code.

🍴
Forks

Your own copy of someone else's repo. Used to propose changes via PR back to the original.

⭐
Stars / Watch

Star = bookmark. Watch = get notified of activity. Stars are also a popularity signal — useful for evaluating libraries.

The Marketplace

GitHub Marketplace — what it actually is

The GitHub Marketplace is GitHub's app store. Two main categories:

1. Apps (integrations that act on your repos)

Third-party services that get permission to read/write your repos. They show up as comments, status checks, or automated PRs.

  • Vercel / Netlify — auto-deploy your site on every push. Free tiers.
  • Codecov / Coveralls — code coverage reporting.
  • Snyk / Dependabot — security vulnerability scanning.
  • Linear / Jira — link issues across PMtools.
  • Sentry — error tracking that links errors back to the commit that introduced them.
  • Slack / Discord — post events into your channels.

2. Actions (reusable automation steps)

Pre-built building blocks for GitHub Actions workflows. Most are free.

  • actions/checkout — checks out your repo. Used in nearly every workflow.
  • actions/setup-node, setup-python, setup-go — install language toolchains.
  • actions/cache — cache dependencies between runs (speeds up CI dramatically).
  • peaceiris/actions-gh-pages — deploy to GitHub Pages.
  • JamesIves/github-pages-deploy-action — alternative Pages deploy.
  • aws-actions/configure-aws-credentials — connect to AWS without storing static keys.
  • anthropics/claude-code-action — run Claude Code as a CI step (review PRs, fix issues, etc.).

How to install a Marketplace app

  1. Go to github.com/marketplace and find the app.
  2. Click "Install it for free" (or paid tier).
  3. Choose which repos it can access — single repo or all.
  4. Authorise. The app appears in your repo settings under "Integrations".

How to use a Marketplace Action

Actions go in .github/workflows/[name].yml — a YAML file in your repo. Example: auto-deploy to Pages on every push to main.

name: Deploy to GitHub Pages
on:
  push:
    branches: [main]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./   # folder to publish

Push that file. Next push triggers the workflow → site goes live.

AI on GitHub

Plug AI into your repos

Claude Code Action

Anthropic's official Action lets you trigger Claude Code from a GitHub workflow — run code reviews, fix issues mentioned in PR comments, generate release notes.

  • Repo: github.com/anthropics/claude-code-action
  • Trigger Claude in a PR comment: mention @claude with a request, e.g. "@claude please add tests for the new auth function".
  • Setup: install the GitHub App + add your Anthropic API key as a repo secret.
name: Claude Code
on:
  issue_comment:
    types: [created]
  pull_request_review_comment:
    types: [created]

jobs:
  claude:
    if: contains(github.event.comment.body, '@claude')
    runs-on: ubuntu-latest
    steps:
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}

GitHub Copilot

GitHub's own AI coding assistant. £8/mo Individual. Inline completion + chat in your IDE. Works in VS Code, JetBrains, Vim, Neovim, Visual Studio.

Cheaper than Cursor / Claude Code but less powerful for big multi-file edits. Best for: "I know what I'm typing, just complete it faster."

Copilot Workspace (separate from Copilot)

Browser-based "describe a feature → AI plans + implements it as a PR" experience. Like Lovable but inside GitHub. Currently in technical preview.

Other AI Actions worth knowing

  • Aider Action — run the open-source aider coding agent in CI.
  • Mentat — AI code editing in PR comments.
  • RepoMix — pack your whole repo as a single file Claude can read in one prompt.
  • OpenAI Workflows — community Actions that call GPT for various tasks (PR titles, changelog generation, translations).
Discovery

Finding the good stuff on GitHub

  • Trending — github.com/trending — top repos this week. Filter by language.
  • Topics — github.com/topics — browse by tag. Useful tags: claude-skills, mcp-server, n8n-templates, ai-agents.
  • Stars sort — search a topic, sort by stars. Quickest way to find proven projects.
  • "Awesome" lists — search "awesome [topic]" — community-curated lists of the best repos for any subject.
  • Code search — github.com/search — search across all public code. Find real-world usage of any library/API.

Awesome lists you should bookmark

Publish

Push your first project to GitHub

# In your project folder
git init
git add .
git commit -m "feat: initial commit"

# Create the GitHub repo + push (with gh CLI)
gh repo create my-project --public --source=. --remote=origin --push

# Or without gh CLI:
# 1. Create the empty repo on github.com manually
# 2. Then:
git remote add origin https://github.com/your-username/my-project.git
git branch -M main
git push -u origin main

Make it look professional

  • Add a README.md — first thing visitors see. What it does, how to use it, screenshot if visual.
  • Add a LICENSE file — MIT is the safest default for open source.
  • Add tags via the repo "About" sidebar — they help discovery.
  • Add a description (one sentence) and link.
  • Add 1-2 screenshots in the README — increases stars by ~3×.
