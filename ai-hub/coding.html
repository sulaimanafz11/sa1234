Claude Code, Cursor, GitHub Copilot, Windsurf, Lovable, v0, Bolt, Replit Agent. They sound similar but each one shines for a different job. This page tells you what each is for, when to pick which, and how to ship a working app this week.

The lazy answer: non-coder who wants a real web app live by Friday → start with Lovable. Want to learn while building → Cursor. Already a developer wanting deep agentic help → Claude Code. Just want fast autocomplete in your existing IDE → Copilot.

Decision tree

Which one for me?

  1. Are you a non-coder? → Lovable (full app) or v0 (just UI). Done.
  2. Are you already a developer using VS Code daily? → Cursor for everyday, add Claude Code for big agentic tasks (refactors, multi-file features).
  3. You want the cheapest AI in your existing IDE (JetBrains, Vim, etc.)? → Copilot at £8/mo.
  4. You want to ship a Next.js MVP in a weekend, browser-based? → Bolt.
  5. You want a hosted "I'll just describe it and click deploy" experience? → Replit Agent.
  6. You want a generous free tier with agentic capabilities? → Windsurf.
Setup that pays off

CLAUDE.md and .cursorrules — the killer move

Both Claude Code and Cursor read a project-specific instructions file on every session. Spending 10 minutes on this saves you from re-explaining your project on every prompt.

What to put in it

  • Stack — language, framework, runtime versions
  • Conventions — naming, formatting rules, file layout
  • Test command — how to run tests in one line
  • What NOT to do — files / patterns to never touch
  • Domain glossary — what your acronyms mean
# Project: [NAME]

## Stack
- Language: [TypeScript / Python / Ruby]
- Framework: [Next.js 15 / FastAPI / Rails 7]
- DB: [Postgres via Prisma]
- Test: `pnpm test`

## Conventions
- Components: PascalCase, one per file, in `src/components/`
- Hooks: `useFoo.ts` in `src/hooks/`
- Server code: in `src/server/`
- No default exports
- Tailwind only — no CSS modules

## Don't do
- Don't run `npm install` — we use pnpm
- Don't touch `src/legacy/*`
- Don't add new dependencies without asking

## Glossary
- "Order" = a customer purchase (not the SQL ORDER BY)
- "Account" = the org-level entity, "User" is per-person
Workflow

Ship something this week

  1. Day 1 — pick the tool (use the tree above), install/sign up, get a "hello world" working.
  2. Day 2 — pick a tiny real project. Examples: a habit tracker, a recipe saver, a stock signal page (like the StockIQ folder in this repo).
  3. Day 3 — write the CLAUDE.md / .cursorrules. Then prompt: "Plan out the MVP in 5–8 features, smallest first."
  4. Day 4–5 — build feature by feature. Always plan-then-do (see Prompting Mastery).
  5. Day 6 — deploy. Vercel for frontend, Supabase for backend, both have generous free tiers.
  6. Day 7 — share it. Post the URL on X / LinkedIn. Counts as a portfolio piece.
The single biggest mistake: trying to one-shot a whole app in a single prompt. Even the best models do better in small steps with feedback. Ship one feature, run it, fix it, ship the next.
