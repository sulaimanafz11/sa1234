Lesson 1

Anatomy of a great prompt

Five ingredients. Skip any of them and quality drops fast.

The five-part structure

  1. Role — who the AI should act as. "You are a senior copywriter who has launched 50+ Shopify brands."
  2. Task — exactly what you want done. "Write 3 product descriptions for a luxury oud fragrance."
  3. Context — what the AI needs to know. "Brand is RIHLA. Audience: 25–45, modern Muslim professionals. Premium positioning, £85 price point."
  4. Format — how you want the output. "Each description: 60–80 words. Headline + 3 sensory bullets + 1 CTA. Markdown."
  5. Constraints — what to avoid + tone. "No clichés like 'transport you'. UK English. Confident, not salesy."

Same task, two prompts

❌ "Write product descriptions for my fragrance."

✅ "You are a senior copywriter (50+ Shopify brand launches). Write 3 product descriptions for RIHLA, a luxury oud fragrance — £85, modern Muslim 25–45 audience, premium positioning. Each: 60–80 words, headline + 3 sensory bullets + 1 CTA. UK English, confident not salesy, no clichés."

The second prompt gets professional output on the first try. The first prompt needs 5 follow-ups.

Lesson 2

System prompt vs user prompt

The two channels

Most AI tools have two layers for instructions, even if the UI hides one:

  • System prompt — the persistent identity / rules. Set once, applies to every message in the chat. Use this for role, tone, constraints, output format.
  • User prompt — the specific request right now. Use this for the task & context that changes message-to-message.

Where you set it

  • ChatGPT / Claude — Custom Instructions / Project instructions. Or start a "Project" with the system prompt baked in.
  • Claude Code — CLAUDE.md at the project root. Read on every session.
  • Cursor — .cursorrules file in the repo.
  • API / SDK — explicit system parameter on the request.
Pro move. Save 3–5 system prompts as Custom GPTs / Claude Projects: "Writing partner", "Code reviewer", "Research analyst", "Email rewriter". You'll stop re-typing the role/tone every time.
Lesson 3

Few-shot examples

Show, don't tell

If you can't describe the style you want clearly, show 2–3 examples instead. The model copies the pattern far better than it follows abstract instructions.

Rewrite these support replies in our brand voice. Examples:

INPUT: "Your order was delayed."
OUTPUT: "Your order took the scenic route — apologies. It lands tomorrow."

INPUT: "We can't refund this."
OUTPUT: "We can't refund this one, but here's what we can do instead — keep reading."

Now rewrite this:
INPUT: "Your subscription has been cancelled."

Three examples is the sweet spot. One isn't enough; ten is overkill and burns tokens.

Lesson 4

Output format & schemas

Tell it the shape you want

Vague output = vague answer. Specifying the structure forces the model to think clearly.

Common formats worth memorising

  • Markdown — for any human-reading output (default)
  • JSON — for anything you'll feed into code
  • Table — for comparisons, decisions, options
  • Numbered steps — for instructions or playbooks
  • YAML / front-matter — for structured config / metadata
Return your answer as JSON with this exact shape:
{
  "summary": "one sentence",
  "key_points": ["point 1", "point 2", "point 3"],
  "risk_score": 1-10,
  "recommendation": "string"
}
No markdown. No commentary outside the JSON.
Lesson 5

Chain-of-thought & planning

Make the model think before it answers

Modern reasoning models do this automatically. For older / faster models, ask explicitly:

  • "Think step-by-step before giving the final answer."
  • "First plan your approach. Then execute."
  • "List the trade-offs of each option, then recommend one."

For complex tasks (code, analysis, decisions), this single line can change a wrong answer into a right one.

Lesson 6

Common mistakes

  1. Asking for too much in one prompt. "Write me a business plan, do market research, generate a logo, and draft 10 ads." Break it into separate prompts in the same chat.
  2. No role. Without one, you get generic averaged-internet output.
  3. No examples for tone. "Write in a casual voice" is meaningless. Show one example of casual voice.
  4. Vague "make it better". Better at what? Shorter? Funnier? More technical? Be specific.
  5. Not iterating. First answer is rarely the best. Reply with: "Tighten this, cut by 30%, keep the metaphor."
  6. Treating it like Google. Single keywords get keyword answers. Sentences get thoughtful answers.
  7. Forgetting to verify. Models hallucinate confidently. For facts, cross-check or use Perplexity.

2. The Code Review Prompt

You are a senior [LANGUAGE] engineer. Review the code below.

For each issue you find, return:
- file:line
- severity (low / medium / high)
- problem (1 sentence)
- fix (1 sentence)

Only flag real issues — no nitpicks about style. Prioritise correctness, security, and obvious performance.

3. The Decision Helper

I'm trying to decide between [OPTION A] and [OPTION B] for [GOAL].

Constraints: [BUDGET / TIME / SKILL / OTHER]
What I value most: [TOP 2-3]
What I'd accept losing: [WHAT'S NEGOTIABLE]

Build a comparison table covering: cost, time-to-value, learning curve, scalability, lock-in. Then give me your recommendation and the strongest counter-argument to it.

4. The Research Brief

Research [TOPIC] and produce a brief I can read in 5 minutes.

Output sections (in order):
1. TL;DR — 3 bullets
2. Why this matters now
3. Top 5 things to know
4. Common misconceptions
5. What to read / watch / try next (3 each)

Cite sources where possible. Flag anything you're uncertain about.

5. The Email Rewriter

Rewrite this email to be: clearer, shorter, and more confident.

Keep: the actual ask, the deadline, any name/dates.
Remove: hedging words ("just", "maybe", "I think"), unnecessary apologies, filler.
Tone: warm but direct. UK English.

6. The Plan-Then-Do Wrapper

7. The Image Prompt Builder

Help me write a prompt for [Midjourney / NanoBanana / Flux] for the following image:

What I want: [DESCRIBE]
Style references: [ARTIST / FILM / GENRE]
Mood: [WORD]
Aspect ratio: [16:9 / 1:1 / 9:16]

Output a single ready-to-paste prompt with: subject, style, lighting, lens/camera, composition, mood, negative prompt. Then explain in 2 lines why each choice matters.

8. The Devil's Advocate

I'm planning to [DECISION / IDEA].

Be my devil's advocate. List the 5 strongest reasons this could fail or be a bad idea, ranked by likelihood × impact. For each, suggest the cheapest test I could run before committing.

Be honest, not encouraging.

9. The Meeting Summariser

Below is a meeting transcript. Produce:

1. **Decisions made** (bullet list, names of who decided)
2. **Action items** (table: Owner | Action | Deadline)
3. **Open questions** (bullets)
4. **Risks / red flags** (bullets — only if genuine)

If something was discussed but not decided, put it under Open questions, not Decisions.

10. The Learning Plan

I want to learn [TOPIC]. I have [HOURS/WEEK] and [WEEKS] to get to [LEVEL — beginner usable / interview-ready / expert].

Build me a week-by-week plan with:
- Weekly goal (1 sentence)
- 1 free resource (article / video / docs)
- 1 hands-on project to ship that week
- 1 question I should be able to answer by Sunday

Be realistic about pace. Front-load the highest-leverage concepts.
