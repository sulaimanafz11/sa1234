Part 1

Install Claude Code on Windows & Mac

Claude Code is Anthropic's official CLI tool. It runs in your terminal and can connect to VS Code, JetBrains, or the Claude web app.

Prerequisites

  • Node.js 18+ — download at nodejs.org (pick LTS). This installs both Node and npm.
  • A terminal — Windows: use PowerShell or Windows Terminal. Mac: use Terminal or iTerm2.
  • A Claude account — Pro or Max plan required for Claude Code. Sign up at claude.ai.

Install (both platforms, same command)

npm install -g @anthropic-ai/claude-code

First run

# Navigate to any project folder first
cd my-project

# Then run
claude

On first run it opens your browser and asks you to log in with your Anthropic account. After that it stays authenticated. You're done.

Windows-specific notes

  • If you get a permissions error on install, run PowerShell as Administrator and try again.
  • If claude isn't found after install, close and reopen your terminal — it updates PATH on shell restart.
  • Windows Defender may flag the binary on first run — allow it. It's safe.
  • WSL2 (Linux inside Windows) works perfectly and is often a smoother experience for developers.

Mac-specific notes

  • If you get an error about EACCES permissions, never use sudo npm install -g. Instead, fix npm permissions: npm docs on this.
  • Homebrew users: install Node via brew install node instead of downloading the installer — avoids permission issues.

Connect to your IDE

VS Code

  1. Open VS Code → Extensions (Ctrl+Shift+X / Cmd+Shift+X)
  2. Search for "Claude Code" by Anthropic → Install
  3. The extension adds a Claude panel on the left sidebar
  4. First use: it'll ask you to log in via the CLI (same account)

JetBrains (IntelliJ, PyCharm, WebStorm, etc.)

  1. Settings → Plugins → search "Claude Code" → Install
  2. Restart the IDE
  3. A Claude tool window appears at the bottom

Claude Code Web (no install needed)

Visit claude.ai/code — runs Claude Code in your browser with a sandboxed environment. Good for: trying it out, working on other people's machines, or when you don't have CLI access. This is the version running right now in this NEXUS session.

Part 2

settings.json — the config that runs everything

Claude Code has two levels of settings:

  • User-level — applies to every project. Lives at ~/.claude/settings.json (Mac/Linux) or %APPDATA%\Claude\settings.json (Windows).
  • Project-level — applies only to this folder. Lives at .claude/settings.json inside the repo.

Project settings override user settings for that project.

Starter user-level settings.json

{
  "theme": "dark",
  "model": "claude-sonnet-4-6",
  "autoApprove": ["Bash(git status)", "Bash(git log)", "Bash(git diff)", "Read"],
  "env": {
    "ANTHROPIC_MODEL": "claude-sonnet-4-6"
  }
}

What autoApprove does

Any tool listed in autoApprove runs without asking permission. Put safe read-only things here to reduce interruptions. Never put Bash(rm or Bash(git push in there.

Hooks (run code on events)

Hooks fire shell commands on events like session start, file edit, or tool use. Example: auto-run linter after every file edit:

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [{ "type": "command", "command": "npm run lint --silent" }]
      }
    ],
    "Stop": [
      {
        "hooks": [{ "type": "command", "command": "echo 'Claude stopped'" }]
      }
    ]
  }
}
Part 3

CLAUDE.md — your project's permanent memory

Place a CLAUDE.md file at the root of any project and Claude Code reads it automatically on every session. It's your project's standing instructions — stack, conventions, test commands, what not to do, domain glossary.

Think of it as the briefing you'd give a new senior developer on day one, so you never have to repeat yourself.

Where it lives

  • ./CLAUDE.md — project root (most common)
  • ~/.claude/CLAUDE.md — user-level, applies everywhere
  • ./src/CLAUDE.md — sub-folder level (applies when Claude is working in that folder)

Minimal starter template (any project)

# [PROJECT NAME]

## Stack
- Language + version:
- Framework + version:
- DB:
- Package manager: (npm / pnpm / yarn / pip / cargo)
- Run dev: `[command]`
- Run tests: `[command]`
- Run lint: `[command]`

## Conventions
- [naming conventions, file layout, style rules]
- [any non-obvious patterns you use]

## Never do
- [things to avoid, files not to touch, commands not to run]

## Domain glossary
- [term]: [what it means in THIS project]

User-level CLAUDE.md (applies to all projects)

# Global preferences

## My style
- I prefer TypeScript over JavaScript
- Always use pnpm, never npm or yarn
- Tailwind CSS only — no CSS-in-JS, no SCSS
- Named exports only — no default exports
- Write tests for any new functions I ask for
- UK English in comments and user-facing text

## Commit messages
- Conventional Commits format: feat/fix/chore/docs/refactor/test
- Imperative mood: "add feature" not "added feature"
- Max 72 chars in subject line

## Things I hate
- Adding comments that just describe what the code does
- Markdown in responses when I'm asking a quick question
- Suggesting I "consider" something — just do it or say why not
Part 4

Claude.ai Projects — your persistent AI workspace

Projects (on claude.ai) are persistent, context-aware workspaces. Each one has:

  • A system prompt ("Project instructions") that applies to every conversation in the project
  • File uploads that stay in context permanently — docs, PDFs, code files, brand guidelines
  • A conversation history that persists between sessions (unlike regular chats)

How to create one

  1. Go to claude.ai → left sidebar → "New Project"
  2. Give it a name (e.g. "NEXUS Work", "Client — Acme Corp", "Writing Partner")
  3. Click "Project instructions" and paste your system prompt
  4. Upload any reference files (brand guide, code samples, previous work)
  5. Start chatting — Claude has all of that context every time

5 Projects worth creating right now

✎ Writing Partner

Upload 5 examples of your past writing. System prompt: "You are my writing partner. Match my voice exactly. When I share a draft, rewrite it to be 30% shorter and 2× more confident."

⌬ Code Reviewer

Upload your CLAUDE.md. System prompt: "You review my code. Flag real issues only: correctness, security, performance. Skip style preferences."

🔍 Research Analyst

System prompt: "You produce 5-minute research briefs. Always: TL;DR, why it matters now, top 5 things to know, misconceptions, what to read next. Cite sources. Flag uncertainty."

💼 Client Work (one per client)

Upload: their brand guidelines, previous deliverables, contracts. System prompt: "You are helping me work on [CLIENT]. Know their brand, tone, goals, and history."

System prompt template to copy into any Project

## Role
You are [ROLE — what this project is for].

## Context
[What I'm working on. Background I never want to re-explain.]

## My style preferences
[Tone, format preferences, UK/US English, etc.]

## Output format
[How you should structure your responses by default.]

## What to do by default
[Standing instructions — e.g. "Always ask one clarifying question before a long task."]

## What NOT to do
[Things that annoy me or waste time — e.g. "Never add a disclaimer paragraph at the end."]
Part 5

Custom GPTs (ChatGPT) — same idea, different platform

If you use ChatGPT Plus, Custom GPTs are your equivalent of Claude Projects. You build a GPT once and it has a persistent system prompt, optional file knowledge, and optionally browsing / code interpreter / image gen baked in.

How to create one

  1. Go to chat.openai.com → top-left menu → "Explore GPTs" → "Create"
  2. Use the builder or click "Configure" to write the system prompt directly
  3. Upload files in "Knowledge" — it uses RAG to answer questions from them
  4. Toggle: Web browsing, DALL-E, Code Interpreter
  5. Save → it appears in your sidebar for instant access

GPTs vs Claude Projects — which one?

FeatureClaude ProjectsCustom GPT
Persistent instructions✅✅
File uploads✅ (full context)✅ (RAG-based)
Memory across chats✅⚠ Limited
Image generation❌ (Claude only)✅ DALL-E built in
Code interpreter❌✅
Share with others❌ (private)✅ public GPT store
Answer quality (writing/reasoning)Claude usually winsGPT-5 competitive

Verdict: Use Claude Projects for serious writing/research/code work. Custom GPTs when you need image gen, code interpreter, or to share a GPT publicly.

Part 6

MCP servers — give Claude Code new tools

MCP (Model Context Protocol) is how you plug extra tools into Claude Code. Think of it like browser extensions, but for your AI agent — each MCP server adds new capabilities.

Popular MCP servers to install

ServerWhat it gives ClaudeInstall
filesystemRead/write files anywhere on your system@modelcontextprotocol/server-filesystem
githubRead repos, issues, PRs via natural language@modelcontextprotocol/server-github
postgresQuery your Postgres DB in plain English@modelcontextprotocol/server-postgres
puppeteerBrowse websites, take screenshots@modelcontextprotocol/server-puppeteer
brave-searchSearch the web (real-time)@modelcontextprotocol/server-brave-search
slackRead/send Slack messages@modelcontextprotocol/server-slack
notionRead/write Notion pages and DBs@suekou/mcp-notion-server

How to install an MCP server

# Inside a Claude Code session
/mcp add github

# Or edit ~/.claude/settings.json manually:
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "your_token_here"
      }
    }
  }
}

Full list of official servers: github.com/modelcontextprotocol/servers
